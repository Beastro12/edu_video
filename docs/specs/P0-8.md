# Spec — P0-8: a temporary google-genai Client closes its own HTTP client (every still fails)

Found by reviewer a43d9 (P3-6 review C1). The orchestrator reproduced it with
scratchpad/orch/genai_lifetime.py: the real SDK with the transport faked.

## The bug (verified)
- `agents/image_agent.py:53` calls `google_client.make().models.generate_content(...)` inline.
- With google-genai 2.25.0, the temporary `genai.Client` is collected as soon as `.models` is
  read.
  - Its `__del__` (google/genai/client.py:663) calls `close()`.
  - `close()` closes the SDK-owned httpx client, unless the caller supplied one
    (_api_client.py:2499).
- The request then fails before it is sent: `RuntimeError: Cannot send a request, as the
  client has been closed.` Probe result: inline gives that error with 0 requests at the
  transport; with the client kept in a variable, 1 request and OK.
- **Effect on a real run:**
  - every still raises and falls back to Manim (D7), recorded in failures.json;
  - the thumbnail falls back to a frame;
  - no money is spent, but the film loses every picture. This repeats D13's "every still
    silently became Manim".
- `agents/ai_video.py:73` keeps its client, so Veo is not affected. P3-6's preflight.py:205 has
  the same inline pattern and is fixed in P3-6's own fix round, not here.
- **Why no test caught it:**
  - every test replaces `google_client.make()` with a fake, so the SDK's object lifetime never
    runs;
  - the real-SDK tests pass `httpx_client=mock`, which `close()` skips.

## Accept
1. Every pipeline call through a genai Client keeps the Client referenced for the whole call:
   `client = google_client.make()`, then `client.models...`. Add a one-line comment at the site
   saying why.
2. Regression test: drive the REAL SDK with its OWN httpx client.
   - Patch `httpx.HTTPTransport.handle_request` to answer a valid image response: one part with
     inline_data, synthetic PNG bytes.
   - Call `image_agent._buy(scene, out)` and assert that the file is written and the transport
     got exactly 1 request.
   - On 81c59dc's image_agent.py this test FAILS with "client has been closed". Show it.
3. Guard test for the class:
   - an AST scan of `agents/`, `scripts/` and the root `*.py` modules finds no attribute access
     on the direct result of `google_client.make(...)` (e.g. `google_client.make().models`);
   - it fails on base.
4. No paid cache key changes (D9). No behaviour change besides the request now being sent.

## Design-check changes (Opus a43d9, 2026-10-25). Binding; they override anything above.
1. **Sites at d6df6f4:** only agents/image_agent.py:53.
   - Both pipeline stills (pipeline.py:297 → reviewed_still → render_still) and the thumbnail
     (thumbnail.py:353 → render_still) reach it, so the thumbnail invariant is answered: covered.
   - still_critic uses Claude, and Anthropic resources hold their client, so it is not affected.
   - ai_video.py:73 keeps its client.
2. **Regression test (Accept 2):**
   - it uses the `real_google` fixture and sets `config.GOOGLE_API_KEY`;
   - it asserts the file's bytes equal the PNG;
   - it proves no socket opens with an in-test guard: `monkeypatch.setattr(socket.socket,
     "connect", <raise>)` for AF_INET/AF_INET6;
   - on base it fails with the "client has been closed" text, not with PaidCallInOfflineTest.
3. **AST guard (replaces Accept 3's scan rule):**
   - Resolve the factory by import:
     - module aliases of `agents.google_client` (`from agents import google_client [as x]`,
       `import agents.google_client as x`);
     - function aliases (`from agents.google_client import make [as y]`);
     - `genai.Client` and `from google.genai import Client`.
   - Never match a bare `make` by name: thumbnail.make and bench_stills' local make exist.
   - Flag any `ast.Attribute` whose value is a call to one of these.
   - Scan agents/ and scripts/ recursively, plus the root *.py files. Skip tests/, .venv/ and
     build/.
   - Include a self-test:
     - it flags `google_client.make().models`, `gc.make().files`, `make().models`,
       `mk().operations`, `g.make().models`, `genai.Client(api_key=k).models` and
       `Client().models`;
     - it does not flag `c = google_client.make(); c.models.get()`,
       `with google_client.make() as c: c.models`, `assembly.make().x`, or a locally defined
       `make`.
   - Known limit, stated in the test docstring: an attribute of a local Client returned from a
     function.
   - The reviewer's working version is at
     scratchpad/probes/p0-8-design/test_genai_lifetime_probe.py; you may start from it.
4. **Ordering:** once this is on auto/dev, the AST guard also covers P3-6's scripts/preflight.py.
   P3-6's fix round fixes line 205 and runs make check on top of P0-8.
